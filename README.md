# Виджет лимитов Claude

Маленькое плавающее окно поверх всех окон: лимит за 5 часов, недельный лимит, время до сброса.
Нужен Python 3.10+ с tkinter (в установщике python.org он есть). Ничего ставить через pip не нужно.

## Запуск
Двойной клик по `run.bat` или `python limits_widget.py`.
Левая кнопка мыши: перетащить. Правая: меню (источник данных, прозрачность, выход).

## Источник данных
**Из файла (по умолчанию).** Строка состояния Claude Code записывает лимиты в
`%USERPROFILE%\.claude\limits-snapshot.json`, виджет читает файл. Официальный путь, но данные
обновляются только пока работает Claude Code (в терминале), а работа в Чате цифры не двигает.

Подключение (PowerShell; делает копию settings.json и не трогает уже настроенную строку состояния):

```powershell
$d="$env:USERPROFILE\.claude"; $p="$d\settings.json"
New-Item -ItemType Directory -Force $d | Out-Null
if (Test-Path $p) { Copy-Item $p "$p.bak"; $j = Get-Content $p -Raw | ConvertFrom-Json } else { $j = [pscustomobject]@{} }
if ($j.statusLine) { Write-Host "statusLine уже настроена, ничего не меняю" } else {
  $j | Add-Member -NotePropertyName statusLine -NotePropertyValue ([pscustomobject]@{type="command"; command="python <папка проекта>\limits_statusline.py"})
  [IO.File]::WriteAllText($p, ($j | ConvertTo-Json -Depth 20), (New-Object Text.UTF8Encoding $false)) }
```

**Live.** Виджет сам запрашивает неофициальный адрес Anthropic с токеном входа Claude Code из
`.credentials.json`. Цифры живые, в том числе от работы в Чате, но способ недокументирован: возможны
нарушение условий использования, поломка при изменении формата и ответы 429. Запрос раз в 2 минуты.
Токен обновляется самим Claude Code: если виджет пишет, что токен истёк, запусти `claude`.
Включается в меню с подтверждением.

## Обновление входа
В режиме Live токен Claude Code живёт недолго. Когда он истёк, на виджете появляется кнопка
**«Обновить вход»**, она запускает `claude` в фоне (сначала бесплатная `claude auth status`, а если
не помогло, один крошечный запрос на модели haiku) и проверяет, что токен обновился.
Пункт меню «Автоматически обновлять вход в Live» делает то же без нажатия: не чаще раза в 30 минут и
не больше 3 неудач подряд, потом ждёт ручного нажатия.

## Вид и настройки
Всё в меню правой кнопки: вид (шкалы или кольца), размер, тема, цвет шкал, прозрачность, компактный режим,
пульсация при 90%+, прилипание к краям, «бледнеть без мыши», скруглённые углы (только Windows,
экспериментально), фильтр строк, «Сырой ответ». Клик по виджету переключает «через сколько» и «во сколько» сброс.

## Темп, прогноз, уведомления, история
- **Метка темпа.** Вертикальная черта на шкале (или засечка на кольце) показывает, где была бы шкала при
  ровном расходе: доля прошедшего времени окна. Шкала правее черты значит, что тратишь быстрее ровного темпа.
- **Прогноз.** Если при среднем темпе с начала окна лимит кончится раньше сброса, под шкалой появится
  «При таком темпе кончится в 16:20». В первые 5% окна прогноз не показывается: данных мало.
- **Уведомления.** Когда окно переходит 80% или 90%, рядом с виджетом всплывает окошко со звуком
  (закрывается через 10 с или по клику). Если окно переходило порог, сообщается и о его сбросе.
  При запуске виджета уже набранные проценты не объявляются. Уведомляются только показанные лимиты.
- **История.** Замеры пишутся в `%USERPROFILE%\.claude-limits-history.jsonl` (строка на новый снимок с
  изменившимися цифрами, иначе раз в 30 минут). Больше 1 МБ: файл переименовывается в `.1`, старый архив удаляется.

Всё это выключается в меню: «Темп и прогноз исчерпания», «Уведомлять о 80/90% и сбросе», «Писать историю замеров».

## Проверка
`python -m unittest test_core test_widget_smoke`: разбор данных, чтение файлов, обновление входа и дымовой тест окна
(на поддельном tkinter: ловит ошибки в коде, но внешний вид не проверяет).
